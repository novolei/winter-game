# 《长夜将尽》UI/UX 设计文档

*The Last Long Night* · 项目代号 `WinterTime` · 2026-08-12

本文档与 [GDD](2026-08-11-winter-survival-gdd.md)、[美术圣经](2026-08-11-winter-survival-art-bible.md)、[系统地图](2026-08-11-winter-survival-system-map.md) 同级，是 UI 的**验收标准**。每个界面、每个提示、每条动效交付时对照本文打分。

## 0. 这份文档要解决的冲突

GDD 第三支柱是**「沉默即叙事——没有 HUD、没有旁白，世界自己说话」**，第一支柱明文否决**「任何非叙事化的 UI」**，§11 更进一步：**Tab 是全游戏唯一显示数值的时刻**。

同时 PROGRESS.md 的风险登记挂着一条未关闭的风险：**「五条生存条的 UI 表达与极简美术冲突 · 监控中」**。

这两件事是同一件事。本文档的存在就是为了关掉它。

**结论先写在这里：这个游戏有 UI，但它没有 HUD。**

| | HUD | 本作的 UI |
|---|---|---|
| 存在时机 | 常驻 | 只在**变化发生时**存在 |
| 信息 | 数值 | **后果**（"手指不听使唤了"，不是"冻伤 34%"） |
| 锚点 | 屏幕角落 | **世界坐标**——提示长在门上，不长在屏幕上 |
| 消失 | 不消失 | 每个元素诞生时就带着自己的死期 |

一个常驻的状态条会替玩家把世界读完，玩家就不再看世界了——**那才是对第三支柱的真正伤害**，而不是"屏幕上出现了像素"这件事本身。

所以本文档全篇的判据只有一句：**这个元素消失之后，玩家是否仍然必须看世界？** 是，则通过。

## 1. 设计语言：「呵」BREATH

### 1.1 核心隐喻

整套 UI 的组织隐喻是**呵在冷玻璃上的一口气**。

这不是修辞，它是一条可执行的规范。所有 UI 元素的生命周期都遵循呵气的物理：从无到有是**快的、有机的、带一点过冲的**；从有到无是**慢的、边缘先化开的、向上飘的**。

它同时给出两个相反的品质：

- **juice** 来自「呵」——200ms 内完成的、带 1.02 过冲的绽放，配一声吸气
- **空灵** 来自「散」——900ms 的、模糊递增的、上飘 8px 的消失

### 1.2 三段式：呵 · 持 · 散

**UI 照抄这个游戏自己的法则。** GDD §7 给天气定的铁律是三段式：`预兆期 → 持续期 → 消退期`，理由是「无预警的风暴不是难度，是不公平」。UI 用**同一套语法**，理由相同——突然出现又突然消失的元素是对玩家注意力的偷袭。

```
呵 BLOOM   200ms   cubic-bezier(.16, 1, .3, 1)
           scale .94 → 1.02 → 1.00 · blur 4px → 0 · opacity 0 → 1

持 HOLD    2000ms  静止。暖色元素以 0.25 Hz 呼吸，其余不动

散 DRIFT   900ms   cubic-bezier(.4, 0, .7, .2)
           opacity 1 → 0 · blur 0 → 3px · translateY 0 → -8px
```

**没有任何元素可以跳过其中任何一段。** 一个瞬间出现的元素、一个瞬间消失的元素，都是这套语言之外的东西。

### 1.3 六条硬规则

| # | 规则 | 它否决什么 |
|---|---|---|
| **1** | **没有矩形。** UI 由弧、笔画、单像素细线构成 | 面板、边框、九宫格背景、带描边的血条、卡片 |
| **2** | **中心 85% 永远是世界。** 所有元素活在 7.5% 的呼吸边界内 | 屏幕中央的任何提示、居中弹窗、全屏遮罩式菜单 |
| **3** | **暖色在 UI 里只有一个含义：热量的存在。** | 用暖色做选中态、hover、按钮高亮、"重要"强调 |
| **4** | **没有东西是常驻的。** 每个元素诞生时就带着自己的死期 | 常驻状态条、小地图、任务追踪、耐久度、准星 |
| **5** | ~~提示锚定世界坐标~~ → **世界坐标是首选，不再是强制**（见下方裁决记录） | — |
| **6** | **每一次呵气都有一个声音。** 视觉与音频同帧诞生 | 无声的 UI 动作 |

**规则 3 是把第一支柱救回来的那一条。** 美术圣经规则 12 把暖色配额给了五样东西：窗、火、信标、卡车、围巾。UI 里的暖色必须服从同一条法律——**UI 里的一个暖像素，必须和世界里的一个暖像素意思相同**。

于是选中态、hover、强调全部用**冷色的明度与笔画粗细**来做。这会让整套 UI 看起来比一般游戏冷得多。**那是对的。** 这个游戏关于冷。

**规则 4 的唯一例外**写在 §5.5，并且在那里给出了它为什么不算例外的理由。

## 2. 设计令牌 Design Tokens

### 2.1 颜色

**全部派生自 `data/palette/color_bible.tres`，UI 代码不得出现十六进制字面量**（常驻简报约束 6）。下表的"取自"列是唯一合法的取值路径。

| 令牌 | 取自 | 值 | 用途 |
|---|---|---|---|
| `ink/primary` | `snow_tones[0]` | `#8FB0D8` | 主文本、主笔画、选中态 |
| `ink/secondary` | `snow_tones[2]` | `#748FBB` | 说明文字、次要笔画 |
| `ink/muted` | `snow_tones[4]` | `#5D7BA6` | 未选中、禁用、不可用选项 |
| `line/hairline` | `structure_tones[0]` | `#33496E` | 分隔线、弧的底槽 |
| `line/deep` | `structure_tones[2]` | `#1C2A45` | 弧的底槽（暗场下） |
| `scrim/veil` | `structure_tones[3]` | `#131C30` | 遮罩、暗场、结局淡出 |
| `life/warm` | `warm_tones[2]` | `#FFB257` | **热量的存在**——火、信标、温度恢复、室内 |
| `life/ember` | `warm_tones[1]` | `#A05A35` | 暖色的暗档——火将熄、余烬 |
| `alarm/blood` | `warm_tones[0]` | `#6E2F2E` | **仅**伤害与死亡 |

`alarm/blood` 是卡车的颜色，也是三个暖色里最暗的一个。把它专用于伤害与死亡，意味着它**永远不会和 `life/warm` 抢戏**——一个是"你活着"，一个是"你在失去"，两者在色相上是同族，在明度上隔了两档。

**不透明度阶梯**：`100 / 72 / 48 / 24 / 12`。没有中间值。

### 2.2 字体

三族，全部 **SIL OFL 1.1**，可随游戏发行且无需游戏内署名。文件已在 `assets/fonts/`，安装与 Godot 接线见 [assets/fonts/README.md](../../../assets/fonts/README.md)。

| 族 | 中文 | 拉丁 | 用途 |
|---|---|---|---|
| **展示 Display** | Noto Serif SC `wght 200` | Cormorant Garamond `wght 300` | 标题、结局、日次 |
| **界面 Interface** | Noto Sans SC `wght 300` | Inter `wght 300` · `opsz` = 实际字号 | 菜单、提示、物品名 |
| **仪表 Instrument** | —（只排数字） | IBM Plex Mono Light · `tnum 1` | Tab 读数、时间、燃料秒数 |

「思源宋体 / 思源黑体」与「Noto Serif SC / Noto Sans SC」是同一套设计的两个发行名。取 Noto 版，因为它在 Google Fonts 与 `notofonts/noto-cjk` 上有稳定的可变字体版本。

**为什么展示字是宋体/衬线。** 空灵来自笔画粗细的对比与横竖之间的呼吸。黑体是均匀的，它安静但不空灵。Noto Serif SC 200 的横画细到接近消失，正是"呵在玻璃上"的质感。

**为什么拉丁展示字是 Cormorant，判据是笔画对比而不是气质。** 四个候选做过并排字样（[type-specimen.jpg](../../prototypes/type-specimen.jpg)）：Spectral 200 对比低、粗细均匀，紧挨着 CJK 会读成另一个声音；Italiana 太脆，全大写副标题会碎掉，且只有一个字重；Marcellus 太厚太暖，与 CJK 的发丝线不在一个体系。**Cormorant Garamond 300 的高对比与极细发丝线，是唯一在结构上呼应 Noto Serif SC 200 的一个**——两者的纤细是同一种纤细。

**为什么仪表字是等宽且必须是表格数字。** Tab 读数每帧都在变。比例数字会让 `68%` 变成 `71%` 时整行左右抖动，这在一个讲究安静的界面里是致命的噪音。`tnum` 是硬要求，不是偏好。

> **两条从字体文件本身查出来的事实，写在这里以免有人再查一次。**
>
> **一、`NotoSerifSC-VF` 的字重轴下限是 200，不是 100。** ExtraLight 已经是它能到的最细一档。设计要的正是这一档，但想再细是调不动的。
>
> **二、Godot 里拉丁必须是主字体，中文必须是回退字体，顺序反了不会报错。** Noto Serif SC 与 Noto Sans SC **自带一套拉丁字形**。Godot 逐字形解析主字体、再落回退，所以把 Noto 放主位，它自己的拉丁永远命中，**Cormorant 与 Inter 一次都不会被用到**——字照样显示，只是显示的不是选定的那一套。README 里有正确写法。
>
> **排版补偿**：Cormorant 是 Garamond 血统，x-height 明显偏小。分行出现时不必补偿；与中文**同行混排**时，拉丁字号取 **1.15×** 才视觉等大。

#### 字号阶梯（1920×1080 参考分辨率）

窗口拉伸是 `canvas_items` / `expand`（系统地图 §8），下表数值在 1080p 参考空间内定义，随画布自动缩放。

| 级别 | 字号 | 行高 | 字距 拉丁 / 中文 | 族 | 用途 |

| Display L | 56 | 1.15 | +0.20em / +0.12em | 展示 | 结局标题、「第四日」 |
| Title | 34 | 1.25 | +0.16em / +0.10em | 展示 | 菜单项、分组标题 |
| Body L | 22 | 1.55 | +0.06em / +0.08em | 界面 | 设置项、物品名、提示动词 |

### 2.3 间距与呼吸边界

- **基准网格 8px**（1080p 参考空间）。所有间距是 8 的整数倍
- **呼吸边界 = 屏幕短边的 7.5%**。1080p 下为 **81px**，取整 **80px**，四边相同

取短边而非各自取边，是为了在 `expand` 拉伸下宽屏与 4:3 的边界视觉宽度一致。所有非世界元素必须完全落在这个边界内侧——**中心 85% 是世界的，不许碰**（规则 2）。

### 2.4 动效曲线表

| 名 | 时长 | 缓动 | 用途 |
|---|---|---|---|
| `呵 bloom` | 200ms | `cubic-bezier(.16, 1, .3, 1)` | 元素诞生（默认） |
| `呵·重 bloom-heavy` | 320ms | `cubic-bezier(.16, 1.2, .3, 1)` | 昼夜更替、结局、Tab 开启 |
| `持 hold` | 2000ms | 线性 | 默认停留 |
| `散 drift` | 900ms | `cubic-bezier(.4, 0, .7, .2)` | 元素消散（默认） |
| `散·快 drift-fast` | 400ms | 同上 | 离开交互范围（离开应当干脆） |
| `散·长 drift-long` | 1600ms | 同上 | 结局、日次、火熄 |
| `呼吸 breathe` | 4000ms 循环 | `ease-in-out` | 暖色元素 0.25 Hz 明暗，振幅 ±14% |
| `颤 shiver` | 83ms 循环 | `steps(2)` | 濒危时 1px 位移，12 Hz |
| `涟漪 ripple` | 300ms | `cubic-bezier(.16, 1, .3, 1)` | 交互确认，环 22→64px 同时淡出 |

**寒流事件期间，上表所有时长 ×1.4。** 见 §5.6——这是天气影响 UI 的唯一方式，也是最好的一种。

## 4. 框架层 FRAME

### 4.1 主菜单

**背景是游戏本身。** 一帧实时渲染的农舍夜景，相机锁在同一个 45° 正交角，雪在下，一扇窗亮着。菜单不是盖在游戏前面的一张图——**它就是游戏的一帧**。

**整个主菜单上唯一的暖像素，是农舍那扇窗。**

这是全作的论点陈述句。玩家还没按任何键，就已经知道这个游戏是关于什么的：一片冷蓝里，有一个地方是暖的，你要回到那里去。

**选中态没有暖色，没有背景块，没有箭头。** 只有明度提升 + 一条长出来的线。这就是规则 3 的代价，也是它的收益。

#### 菜单项行为

- **继续** — 仅当存在进行中的一局时出现。不存在时**整项不渲染**，而不是渲染成禁用态
- **新的一夜** — 存在进行中的一局时，触发永久死亡确认（下）
- **设置** — §4.2
- **离开** — 直接退出，无二次确认。这是一个关于放弃的游戏

#### 永久死亡确认

GDD §1：**永久死亡，从第一天重来**。所以没有存档槽，一局就是一局。开新局等于抹掉旧局，这必须挡一下——但要用这个游戏的语气挡。

```
        第 四 日 的一切会消失。

        开  始          返  回
```

- 主句 Display L 56 · `ink/primary`。日次数字用仪表字，其余用展示字
- 两个选项 Title 34，横排，间距 96px，默认焦点在**返回**
- 无遮罩色块，只把背景 3D 压暗 55%（`scrim/veil`）

### 4.2 设置

四组：**画面 · 声音 · 操作 · 辅助**。分组标题 Title 34 `ink/secondary`，项 Body L 22。

**控件也没有矩形**：

| 控件 | 形态 |
|---|---|
| 滑块 | 1px `line/hairline` 全宽轨道 + 已填段 2px `ink/primary` + 一个 6px 实心圆点。无凹槽、无外框 |
| 开关 | 一条 40px 细线，关时 `ink/muted`，开时 `ink/primary` 且线左端长出一个 4px 圆点 |
| 多选一 | 横排文字，未选 `ink/muted`，选中 `ink/primary` + 下方 1px 线 |
| 数值 | 右对齐，仪表字 Instrument 20，表格数字 |

#### 辅助分组（无障碍，非可选项）

| 项 | 范围 | 默认 | 理由 |
|---|---|---|---|
| 提示停留时长 | 0.5× – 3.0× | 1.0× | 阅读速度差异极大。这是本作**唯一**的难度相关设置，且它不改变生存数值 |
| 提示笔画加粗 | 关 / 开 | 关 | 1px 细线在低分屏与低视力下会消失。开启后所有笔画 ×2 |
| 暖色增强 | 0% – 60% | 0% | 蓝红色觉障碍者难以区分 `life/warm` 与 `ink/primary`。此项**只提升 UI 暖色的饱和度与明度，不改世界**——世界的暖色配额是美术圣经规则 12 的事，UI 无权动它 |
| 屏幕震动 | 关 / 开 | 开 | — |
| 字号 | 90% / 100% / 115% | 100% | 只缩放字，不缩放呼吸边界与弧 |

GDD §13 明确「难度选项」是非目标。上表**没有一项改变生存数值**——它们全部只改变"你能否读到 UI"，与"游戏有多难"无关。这个边界是刻意的。

### 4.3 暂停

时间停止。世界降饱和 40%，压暗 40%（`scrim/veil`）。

```
   第 四 日 · 夜
   ────────────
   剩余  03:14

   继  续
   设  置
   放弃这一夜
   离  开
```

**暂停是全游戏唯一可以安全显示"你在第几天"的地方**，因为时间已经停了，显示它不构成对第三支柱的伤害——玩家没有在用它做实时决策。

- 「放弃这一夜」= 回主菜单，局面保留（不是删档）
- 剩余时间来自 `WorldClock.phase_duration() - phase_elapsed()`

### 4.4 三种结局

GDD §10 的三种结局，UI 的立场各不相同。**这一节是本文档最重要的一节。**

#### 获救 — 第 8 天黎明五盏灯全亮

1. 直升机的探照灯扫过雪地（世界事件，非 UI）
2. 全部 UI 元素在 600ms 内 `散`——包括呼吸边界本身
3. 静默 1200ms，画面上只有世界
4. 单行 Display L 居左于呼吸边界内：**「他们看见你了。」**
5. `散·长` 1600ms，淡入黑

#### 死亡 — 任一生存条归零

由 `survival.died` 驱动，payload 携带致死的那条状态。

1. **五段弧不请自来**——玩家没有按 Tab，但弧绽放了。这是全作唯一一次 UI 违背玩家意志出现，因为身体不再听他的了
2. 弧逐条熄灭，间隔 400ms，**致死的那条最后灭**
3. 最后一条弧熄灭时，`alarm/blood` 闪一次（120ms），然后黑
4. 单行 Display L：**「第 四 日。」**——只报日次，不做评价
5. 淡入黑，`散·长`

#### 被遗弃 — 第 8 天黎明有灯是熄的

GDD §10 原文：**「直升机从头顶飞过，没有看见你。你还活着。屏幕上什么都没发生。然后画面淡出。」**

> ### 这个结局的 UI 设计，是不存在。
>
> 没有标题，没有文字，没有音效，没有淡出提示，没有"返回主菜单"按钮。
> 直升机飞过去，声音远了，然后画面在 6 秒里淡成黑，再过 4 秒，主菜单在黑里淡入。
>
> **任何出现在这里的 UI 元素，都是对这个游戏艺术落点的破坏。**
> 这是一条规则，不是一个风格建议。审查时若发现此处有任何 Control 节点被添加，一律驳回。

### 4.5 蒙太奇 MONTAGE

一段蒙太奇 = 一串镜头 + 站在世界里的叙述文字。用在**开场、继续、获救与死亡两种结局**。

> **两处它不许去，而且都是硬规则。**
>
> **一、「被遗弃」结局没有蒙太奇文字。** §4.4 已经裁定那个结局的 UI 设计是**不存在**。相机可以动——直升机飞过去本来就是世界事件——但**一个字都不许写**。那个结局的全部力量在于什么都没发生。
>
> **二、日次转换不用蒙太奇。** 它发生在**游戏进行中**，往那里塞叙述会直接撞第三支柱。日次仍走 §5.4 的呼吸层公告。
>
> 唯一的例外候选是「睡觉推进」——那是玩家主动做出的场景断点，不是游戏替他打断。若要做，按这里的规则做，不要新开一套。

数据在 `data/montage/*.tres`，由 `tools/generate_montages.gd` 产出。加一段蒙太奇是一个新 `.tres`，**零 `.gd` 改动**（约束 4）。

#### 蒙太奇有自己的相机，而且必须有

游戏相机是**正交**的（美术圣经规则 1）。**正交投影没有透视可变**——把它向前推只改变取景，不改变别的。而空间排版（§5.9）**完全由透视变化构成**。

所以每一镜带自己的**透视相机与授权 FOV**。

> **这不违反规则 1。** 规则 1 管的是**游戏被玩的那个视角**：固定、永不旋转、只跟随，好让每一帧都是玩家能学会的构图。蒙太奇按定义就是另一套镜头语言，而且它发生在没人在玩的时候。
>
> 同一条理由让 §4.5 的影像分级也只属于蒙太奇——见下。

#### 一镜的构成

| 字段 | 含义 |
|---|---|
| `duration` | 时长 |
| `camera_from` / `camera_to` | 起止变换，用 `interpolate_with` 插值（旋转 slerp，不是把基矩阵 lerp 压扁） |
| `fov_from` / `fov_to` | 分开写，顺带白送一个变焦推轨——值得留着，且几乎不该用 |
| `camera_ease` | 0 是匀速推轨，1 是两端全缓动。推镜通常要一点但不多：推轨本来就匀速，缓过头读作"被 K 了帧的相机"而不是"被推动的相机" |
| `text` / `text_transform` | 叙述，与它**站立**的世界变换 |
| `text_weight_latin` / `text_weight_cjk` | 见 §5.9 —— 比屏幕上的展示字重 |
| `wind` / `scatter_metres` | 风把它带向哪，带多远 |
| `grade` | 影像分级，见下 |

#### 文字必须放得进它自己的镜头

一行的时长**不写在任何地方**——它由字数算出（每字错峰 0.14s，每字的停留相应延长以保证等长可读）。所以**一行加两个字，就悄悄多需要 0.28 秒镜头**。

题字在切镜时还在飞散，最后几个字就丢在半空。除非有人正好看着那一秒，否则它读起来像渲染故障，而不像一个短了四成秒的时长。

`tests/unit/test_montage_data.gd` 对每一个授权镜头断言这个吻合。

#### 影像分级 —— 只属于蒙太奇

`MontageGrade`：景深、空气、辉光、胶片。

> **为什么这条分割是规则而不是方便。**
>
> 美术圣经 §1.2 给**游戏画面**定了两条量化验收线：雪落在**白的 62%**，蓝通道比红通道**高约 121 点**——都是在光照与色调映射之后测的。颗粒、暗角、空气透视会把这些数字**全部**移位。
>
> 所以分级挂在 `Camera3D.environment` 与 `Camera3D.attributes` 上。这两个是**覆盖**：蒙太奇相机在，它们就在；相机一走，世界自己的环境立刻恢复。**没有东西需要还原，所以没有东西会被还原错。**

| 项 | 做法 |
|---|---|
| **景深** | **焦点是量出来的，不是授权的。** 每一个带文字的镜头相机都在动，任何写死的焦距在第二帧就是错的——而且错的方向正好是把文字虚掉，那是全画面唯一必须锐利的东西。导演每帧测量相机到题字的距离，把远景虚化起点放在它后面 `focus_padding` 米处 |
| **雾** | 高度雾 + 轻微空气透视。颜色**从调色板读**（第二档雪色），不在代码里写 |
| **辉光** | 把琥珀色乘过环境的 HDR 阈值。**低于阈值完全不发光**——那正是「辉光没生效」的真实原因 |
| **胶片** | `assets/shaders/montage_film.gdshader`：颗粒 + 暗角。颗粒**按亮度加权**（暗部强、亮部弱），因为真实乳剂就是这样；均匀铺一层噪声读作"脏屏幕"，而且在这个游戏里会正好压在占满画面的雪上。暗角朝 `scrim/veil` 压暗，**不朝黑**——朝黑会在每一帧蒙太奇的边缘放进第十三种颜色 |
| **颗粒种子** | 按 24fps 量化，让颗粒像放映拷贝那样**跳帧**而不是连续爬行。这是全部里面最便宜的一条，也是最像胶片的一条 |

> **分级应该被感觉到，不该被看到。**
>
> 第一版每个数值都是现在的三倍，代码看不出问题，**帧看得出来**：暗角压成隧道，雾把雪从调色板上洗掉（§1.2 的蓝高红 121 点掉到接近零），农舍那面墙糊成一团光。
>
> 判据：**遮住画面四角。如果中间还看得出被调过色，就是过了。**

## 5. 呼吸层 BREATH

**默认状态：零像素。**

### 5.1 交互提示

**锚定世界坐标**（规则 5）。玩家进入某个 `Area3D` 交互区时，提示长在那个东西上，不在屏幕角上。

```
        ╭───╮
        │ E │      ← 环 22px，1px hairline 底槽 + 2px ink/primary
        ╰───╯
        开  门      ← Body L 22，环下 8px
```

| 阶段 | 时长 | 行为 |
|---|---|---|
| 进入范围 | `呵` 200ms | 环从 0.94 绽放，键位字与动词同时淡入 |
| 停留 | — | 静止。**不呼吸、不脉动**——它不是在催你 |
| 离开范围 | `散·快` 400ms | 比默认快。离开一个地方应该干脆 |
| 按下 | `涟漪` 300ms | 环 22→64px 同时淡出，动词上飘 4px 后 `散` |

**动词是具体的**：`开门` / `点火` / `拾取 柴` / `添柴` / `关门`。不用「交互」这种词——它什么也没说。

物品拾取的动词带物品名与图标：`拾取 · 柴`，图标 24px，`ink/primary` 染色。

**同时有多个可交互物时**，只显示最近的一个。这是固定视角游戏，玩家不能转镜头去消歧义，所以 UI 必须替他选。

### 5.2 阈值浮现

由 `survival.threshold_crossed` 驱动。payload 已经携带 `{stat, threshold, comparison, active, value, targets}`——**UI 不需要自己判断任何东西**。

| 位置 | 左侧呼吸边界内，垂直 38% 高度 |
|---|---|
| 构成 | 24px 图标 + 52px 短弧 + 一行 Body 17 文案 |
| 时序 | `呵` 200 / `持` 2400 / `散` 900 |
| 多条同时 | 纵向堆叠，间距 8px，**第 N 条延迟 160×N ms**（错峰是 juice，也是可读性） |
| 恶化 | **一种墨色，由地面亮度在两个色板条目之间挑**：暗场 `ink/primary`，亮场 `line/deep`。图标、弧、文案同色同强度 |
| 濒危（<0.15） | 亮场转 `alarm/blood`；**暗场留在可读的那支墨上**，加 `颤`（见下） |
| 恢复 | 弧反向收拢，`life/warm` 的点从末端走回——**这是暖色在呼吸层唯一的合法用途**，因为它表示热量正在进入身体 |

#### 文案表 —— 说后果，不说数字

**这张表是本文档与 `data/stats/*.tres` 的契约。** 每一行对应一条真实存在的 `ThresholdEffect`。新增一条阈值必须同时在这里加一行文案，否则 UI 会静默地什么也不说。

| 状态 | 阈值 | 数据里真正发生的事 | 浮现文案 |
|---|---|---|---|
| 体温 | 0.50 | `breath:rate ×1.25` | 呼吸变快了 |
| 体温 | 0.35 | 手足冻伤开始累积 | 手脚开始发僵 |
| 体温 | 0.20 | `breath:rate ×1.5` | 牙齿在打颤 |
| 体温 | 0.15 | 冻伤速率 ×2.0 | 四肢正在失去知觉 |
| 饥饿 | 0.30 | `core_temperature 漏失 ×1.5` | 身体产不出热了 |
| 饥饿 | 0.05 | `core_temperature 漏失 ×2.0` | 身体在烧自己取暖 |
| 口渴 | 0.30 | `fatigue:recovery ×0.5` · `vision:focus ×0.85` | 眼前有些发花 |
| 口渴 | 0.05 | `fatigue:recovery ×0.0` | 再怎么歇也缓不过来 |
| 疲劳 | 0.30 | `locomotion:speed ×0.85` · `snow_cost ×1.35` | 腿开始沉 |
| 疲劳 | 0.10 | `locomotion:speed ×0.85`（叠乘） | 每一步都要想一下 |
| 疲劳 | 0.02 | `locomotion:run_speed ×0.0` | 跑不动了 |
| 冻伤·手 | 0.50 | `ignition:speed ×0.6` · `aim:steadiness ×0.7` | 手指不听使唤了 |
| 冻伤·手 | 0.20 | `ignition:speed ×0.5` · `aim:steadiness ×0.6` | 手已经不算是手了 |
| 冻伤·足 | 0.50 | `fatigue 漏失 ×1.25` · `locomotion:speed ×0.85` | 脚底没有知觉 |
| 冻伤·足 | 0.20 | `locomotion:speed ×0.8` | 每一步都踩在别人的脚上 |

**为什么不显示数字。** 「冻伤 34%」要求玩家在脑子里维护一张表。「手指不听使唤了」不要求任何东西——他立刻知道现在不该去点火，该先烤手。**后果比数值更可操作，而且它是叙事的。** 这就是第三支柱在 UI 里的落地方式。

#### 修订 · 墨色由地面挑，不由文档挑

> **本节原来的两支墨在亮场上都不存在，这是量出来的，不是看出来的。**
>
> `ink/primary` 就是 `snow_tones[0]`——**字面意义上雪本身的那个色号**。用
> `tools/capture_threshold_note.tscn` 在真实场景里，对着元素自己那块矩形取样：
>
> | 地面 | 预设 | 实测地面亮度 | 原墨 | 实测对比度 |

> | 阴影带 | `pale_day`（人走开 10 m） | 0.3851 `#86A9DA` | `#8FB0D8` | **1.08 : 1** |
> | 亮天气事件 | `whiteout` | 0.4616 `#95B8E2` | `#8FB0D8` | **1.10 : 1** |

>
> **阴影带比雪面更糟**，这是关键的一条：`ink/primary` 落在雪自己的明暗范围
> **里面**，不在它上面也不在它下面——**没有任何一个时刻的雪是它能分开的**。
>
> 所以墨色**在色板条目之间挑**，规则见 `src/ui/ui_ink.gd`（§5.10 的时刻提示先
> 遇到同一个问题，两处共用同一条判据，不是两份副本）。改后同样的取样：
> **8.55 / 5.93 / 6.98 / 3.78 / 2.84 : 1**。
>
> **三处偏离本节原文，都记在这里：**
>
> 1. **文案不再是 `ink/secondary`，与图标和弧同墨同强度。** 「说后果，不说数字」
>    让**那句话就是元素本身**——图标说是哪条状态，弧说到了哪一步，而读不到
>    「手指不听使唤了」的玩家什么也没得到。5.2 要的主次由**尺寸与笔重**承担
>    （24px 图标、3–4px 笔画 对 Body 17），这本来就是规则 3 留给强调的通道。
>    多花一档色板买主次，代价是文案在每种地面上少 1.4 倍对比度，夜里掉到 2 : 1 以下。
> 2. **暗场的濒危不转 `alarm/blood`。** 那个色号是 `#6E2F2E`，亮度 0.055，在夜
>    地面上实测 **1.55 : 1**——**在人最可能被冻死的那种地面上，它是整个元素里最
>    看不见的一支墨**。十二色里没有浅的红，规则 3 不许拿暖色顶替，所以夜里的紧急
>    由本节自己已经给的另外两个通道扛：**笔重**与**颤**；地面一亮，颜色就回来。
> 3. **`ink/muted` 不是答案。** 调色板的浅色半边**就是雪**（1.00–2.00 : 1），
>    最亮的暖色 `#FFB257` 在亮雪上是 1.13 : 1。**在雪上分离靠的是暗，不是更亮，
>    也不是更饱和。**
>
> **仍然没有底板。** 规则 1 不允许，而且也不需要：解在墨里。

### 5.3 拾取回执

左下呼吸边界内。24px 图标 + 物品名 Body L + 数量角标 Instrument S。

`呵` 200 / `持` 1400 / `散` 900。连续拾取同一物品时**不新建元素**，而是把已有的那个数量角标 `呵` 一次并重置 `持` 计时——避免刷屏。

### 5.4 昼夜更替

**这是全游戏最重要的一条信息。** GDD §3：`NIGHTFALL = GO HOME` 是字面意义的死线。

#### 日出 `clock.day_started`

- **「第 四 日」** Display L 56，水平居中、垂直 22%（不是正中——规则 2）
- 日次数字用仪表字，「第」「日」用展示字，三者基线对齐
- `呵·重` 320 / `持` 2600 / `散·长` 1600

#### 入夜 `clock.night_started` — 第 1~5 日

- **「夜」** 单字 Display XL 96
- 其下 **「回  家」** Title 34 `ink/secondary`，延迟 240ms 后 `呵`
- 呼吸边界四边同时有一次从暖到冷的扫掠（1200ms，`life/ember` → 透明）
- 音频：一记低频闷响（见 §8）

#### 入夜 — 第 6~7 日

GDD §4：**第 6 天起，夜里必须冲进黑暗与风暴去重新点燃熄灭的信标。安全时段变成最危险的时段，这一反转是整局的情绪顶点。**

**所以第 6、7 日的入夜，「回家」那一行不再出现。**

只有「夜」，然后什么也没有。

**指令的缺席就是信息本身**——家已经不再是答案了。UI 什么也没多说，但玩家会在那个空白上停一秒。这比任何一句「信标正在熄灭」都更狠，而且它完全不违反第三支柱。

### 5.5 火与室内

#### 火点燃 `stove.lit`

底部呼吸边界，`life/warm` 的一次绽放，`呵` 200 / `持` 600 / `散` 900。

#### 火熄灭 `stove.went_out`

同位置，`life/ember`，`散·长` 1600。慢是重点——火不是"关掉"的，是慢慢没的。

#### 火边的那条线 —— 规则 4 的唯一例外

玩家站在火的温暖半径内时（`Stove.warmth_at() > 0`），底部呼吸边界有**一条 1px `life/warm` 细线，40% 不透明，以 0.25 Hz 呼吸**。

> **为什么它不算违反规则 4。**
>
> 规则 4 禁止的是"表示某个状态的常驻元素"。这条线不表示状态，**它表示一个地方**——它只在你站在火边时存在，你走开两步它就 `散` 了。它是那团火在屏幕边缘的投影，不是一个仪表。
>
> 而且它服从规则 3：它是暖色，它的含义正是"热量的存在"，与世界里火的暖色像素同义。
>
> 判据回到 §0 的那一句：**这条线消失之后，玩家是否仍然必须看世界？** 是——他必须走回火边，而火在世界里。通过。

#### 进入室内 `interior.entered`

美术圣经规则 12 的修订版说得很清楚：**「被揭示的室内像素不设上限，且应当暖色主导。这个反差就是奖励本身。」**

UI 在这一刻的正确行为是**让路**：

- 呼吸边界的四条边在 900ms 内从 `line/hairline` 过渡到 `life/warm` 12% 不透明度
- 除此之外**不新增任何元素**

进屋的奖励是那一屋子暖色，不是一条「你进入了室内」的提示。

### 5.6 天气预兆

GDD §7 铁律：**所有事件必须先预兆再落地。天空就是天气预报 UI。**

**所以 UI 在这里几乎不做事。** 预兆是世界的工作（云、光、风声、雪粒方向），UI 只做一件极轻的补充：预兆期（20-40s）内，呼吸边界的相应边缘有一次极慢的渐变。

| 事件 | UI 表现 |
|---|---|
| 暴雪 | 上边缘泛白，从中点向两端扩散，30s |
| 风向突变 | 左右两边缘中的一边亮起，指示新风向 |
| 短暂放晴 | 无 UI。放晴是奖励，不该被提示打断 |
| 冻雨 | 边缘出现极细的断续刻痕 |
| **寒流** | **无新元素。所有 UI 动效时长 ×1.4** |
| 雪雾 | 全部边缘不透明度降到 24% |

> **寒流这一条是本节存在的理由。**
>
> GDD 给寒流的预兆是「空气变得极静」。所以 UI 也变慢——每个提示的绽放与消散都拖长四成。玩家不会意识到自己读到了什么，但他会**感觉**到有什么不对。
>
> 等他反应过来时，他已经在留一条清晰的足迹了（GDD §8：寒流让足迹长时间不消失）。
>
> **安静既是危险的预兆，也是危险的原因**——这句话现在也是一条 UI 规范。

### 5.7 威胁

GDD §9 的反直觉设计：**危险靠近时抽走 BGM 高频层，用缺失制造恐惧。**

UI 用同一招：`threat.detected_player` 时，**不新增任何元素**，但屏幕上所有 `life/warm` 的东西在 1200ms 内褪成 `ink/muted`。

火边那条线还在，但它不暖了。

`threat.lost_player` 时，暖色在 2400ms 内慢慢回来——比失去慢一倍。

### 5.8 屏幕状态：冷与失焦

两条不属于任何元素、直接作用于整帧的表现，由生存数值连续驱动（不是阈值触发）：

| 来源 | 表现 |
|---|---|
| `core_temperature` 越低 | 四角结霜向内生长。0.5 起可见，0.0 时覆盖约 22% 画面。**永不遮挡角色所在的中心区** |
| `vision:focus` 通道（口渴 <0.3 时为 0.85） | 全画面极轻微失焦（0.4px 高斯），呼吸式起伏 |

这两条不是 UI 元素，是**镜头的状态**。它们没有 `呵/持/散`，它们跟着数值连续变化。写在这里是因为它们和 UI 共享同一套信息职责。

### 5.9 空间排版 SPATIAL TYPOGRAPHY

**呼吸层的世界空间形态。**

它属于第 5 章而不是第 4 章，尽管只有蒙太奇（§4.5）在用它。理由是它就是呼吸层：一行题字是 `呵 → 持 → 散` 的元素，只不过**逐字**地、在三维里发生。同一套包络，同一条规则 4，同一个自带的死期。它不是新语言，是同一门语言换了个介质。

三段命名照抄行业说法：**3D Camera Tracking + 3D Text + Occlusion Compositing**。

#### 三条属性就是全部效果，每一条都是一行代码可以丢掉

| 属性 | 丢掉它会怎样 |
|---|---|
| **billboard 关闭** | billboard 的字会转向相机，于是镜头推进**产生零透视变化**。整个效果塌成"用 3D 画的贴屏叠加"——而且**塌得无声无息**：开场那一帧看着完全正常 |
| **深度测试开启** | 这就是 Occlusion Compositing。关掉它，叙述会画在它本该站在后面的树上，然后它就不在世界里了 |
| **alpha 模式按阶段切** | 见下 |

`tests/unit/test_inscription.gd` **直接断言这三条**，因为截图只有在有人正好看对那一帧时才抓得住。

#### 词 → 字 → 雪粒

溶解**同时发生在三个尺度上**，这是它不读作"一个特效"的原因：

- **词**散开，因为每个字分别被带走
- **字**散开，因为 alpha hash 把它吃掉
- **雪粒**汇入场景里**本来就在下**的雪

**不新建任何粒子。** 山谷自己的天气把最后一步做完。

方向是**风**——同一阵擦掉玩家脚印的风（GDD §8）。叙述服从山谷自己的天气，而不是服从一个屏幕特效。**这是"转场"和"地方"的区别。**

每个字的偏角与旋转由**字序哈希**决定，不是 `randf()`：同一行重播必须一模一样，否则一段蒙太奇两次播放会散得不同。

#### alpha 模式必须按阶段切换

`ALPHA_CUT_HASH` 会抖动**每一个半透明像素**，包括一个完全不透明字形的抗锯齿边缘。整条命周期都开着，文字**在被阅读的全程都是麻点状的**。

> **它是一个溶解，不是一个渲染模式。**
>
> 书写与停留期用干净的 alpha 混合；只有风到了这个字，才切到 hash。
>
> 而且**每帧都设**，不是在跨越那一刻设一次——`seek()` 是一个**擦洗**接口：蒙太奇可能倒放，截图工具可能采样任意时刻，一次性切换会把字形留在它最后经过的那个模式里。

#### 描边的 alpha 也必须驱动

`Label3D` 默认带 **12px 纯黑描边**，而 `outline_modulate` 是**独立于 `modulate` 的另一个颜色**。

只淡出字形，等于只淡出填充——**退场结束时留在画面上的是一个纯黑的字**。这个 bug 真的进过一次截图：整行散成了黑色。

描边**保留而不是关掉**：这行叙述立在 62% 亮度的雪前面，暖色配雪是十二色里唯一没有对比余量的一对。但它取自**最暗的结构色**而不是黑——规则 3 不因为那个像素恰好是边缘就不适用了。

#### 立在世界里的字，比贴在屏幕上的字要重

§2.2 把展示族定在 Noto Serif SC **200**（它字重轴的下限），那对**屏幕上**的字是对的：背景可控，纤细读作空气。

对**空间排版**是错的。一行字立在山谷里，背后是一整片 62% 亮度的雪，**没有任何底**——200 会直接洗进它站着的地面。

**重量是它在外面唯一能买到存在感的东西，而且是在更小的字号上买的。**

| | 屏幕（§2.2） | 世界（§5.9） |
|---|---|---|
| 中文字重 | 200 ExtraLight | **600** |
| 拉丁字重 | 300 Light | **500** |
| 占画幅宽 | — | **0.32** |

0.44 配重字重是"带照片背景的字幕卡"，0.32 配细字重会消失在雪里。**小而重**才读作"立在山谷里的东西"，而不是"盖在山谷上的东西"。

#### 字缘的柔化来自辉光，因为别处没有

`Label3D` 画的是硬 alpha 边，**任何地方都没有模糊可用**。所以把琥珀色乘过环境的 HDR 阈值（`text_emission`），让 bloom 把那条边化成光。

这同时是规则 3 在做它本来的事：**暖 = 热量的存在，而热量会发光。**

#### 世界坐标的位置从相机推算，不从被摄体推算

按被摄体摆放叙述，等于让"它离镜头多远"变成一件**碰运气**的事——而那件事同时决定它是否可读、以及它会不会被埋进景物里。

三镜里有两镜曾经栽在这上面：一行站在 34 米外，渲染出来**七个像素高**；另一行站进了门廊内部，字形与柱子相交，**深度测试完美地把嵌进去的部分全藏了**，画面上只剩每个字露在外面的那一毫米。

> **Occlusion Compositing 用"让文字几乎看不见"证明了自己是活的。**

现在位置沿**相机自己的视轴**给出（`metres_ahead`），于是三件事同时成立：文字立在镜头与被摄体之间的空气里、它面朝推进方向、**它的世界尺度可以被解算而不是被猜**——按目标画幅占比反推 `pixel_size`。

### 5.10 时刻提示

**屏幕底部正中，每 4 小时世界时间出现一次，停留 4 秒，然后消失。**

这是日晷唯一活下来的部分——GDD §3 的 `NIGHTFALL = GO HOME` 是字面意义的死线，玩家必须能对它做计划。**但计划需要的是「现在几点」被告知，不是一个永远盯着你的表。**

> **它为什么在第 5 章而不是第 6 章。**
>
> 它不是玩家召唤出来的，是世界主动说的；它有诞生、有停留、有死期。它是呼吸层的一员，只不过触发它的事件是**时间本身**，而不是身体或天气。

#### 构成

```
              ╭─────────╮
         ☽ ──╯     ●     ╰── ☀        ← 60° 细弧，两端各一个 20px 图标
                                          ● 是当前位置的小圆点
                夜晚 4                  ← 弧下方居中，Body 17 + 仪表字日次
```

| 项 | 规格 |
|---|---|
| 弧 | 60° 跨度，弦长 192 设计像素（= 半径），矢高 25.7 |
| 底槽 | 1px `line/hairline`——**整条弧** |
| 已走过的一段 | 2px `ink/primary`，从**当前阶段那一端**长向标记 |
| 标记 | 3px 实心圆点 `ink/primary`，位于当前进度 |
| 两端图标 | `night_moon.png` 在左、`day_sun.png` 在右，20px。当前阶段那个是 `ink/primary`，另一个是 `ink/muted` |
| 文字 | 阶段词 Body 17 `ink/secondary` + 日次 Instrument `ink/primary`，共基线，弧下 8px 居中 |
| 位置 | 底部呼吸边界内**垂直居中**。整个元素高约 74 设计像素，边界是 81——规则 2 由算术保证，不由自觉保证 |
| 时序 | `呵·重` 320 / `持` 4000 / `散` 900 |

**图标是现成的资产，白色透明底，运行时染色。** 不画、不生成——`assets/ui/icons/day_sun.png` 与 `night_moon.png` 已经在库里。

#### 走向就是信息

两个图标**固定不动**：月在左，日在右。**变化的是标记往哪边走，而它永远走向即将到来的那个阶段。**

| 阶段 | 标记 | 读作 |
|---|---|---|
| 夜晚 | 月 → 日（左往右） | 夜在过去，黎明在那一头 |
| 白天 | 日 → 月（右往左） | 天在过去，**该回家了** |

**另一种做法——永远从左往右——在夜里读对，在白天读反**，而白天恰好是读反了要付代价的那一半。亮起来的那段弧从玩家所在的阶段长出来，所以一个形状同时回答了「现在是哪个阶段」和「走了多远」。

#### 「4 小时」是一个关系，不是一个常数

**一小时 = 当日 `daylight_seconds + night_seconds` 的二十四分之一。** 七天的日程各不相同（第一天 600/300，第七天 240/660），提示按**正在玩的那一天**换算。

把周期写成 150 秒也能跑，而且今天是对的——直到有人重新调一天的节奏，然后它就静默地不对了。这是本项目已经付过两次学费的同一类缺陷（冷却写死对不上片段长度、暖色配额从没对着画面量过）。`tests/unit/test_time_prompt.gd` 断言的是**这个关系**，对着 `data/schedule/*.tres` 的真实秒数算。

#### 弹性只在运动里，不在不透明度里

所有者要的是**弹性**的淡入淡出。这里的做法是：**过冲落在 scale 与退场的上飘上，不落在 alpha 上。**

理由是本项目量过的一个数：`呵·重` 的贝塞尔第一控制点在 y = 1.2，**把它用在一个被钳制的量上，元素会提前到达、贴着上限停住、然后回落一下**——读起来像故障，不像弹性。实测该曲线在 alpha 上返回过 **1.0044**。

所以：`scale` 从 0.94 冲到 **1.02100**（曲线本身的过冲带出来的那一点点，就是弹性的来源），再落回 1.0；退场上飘 8px；**不透明度只单调上升**。`Breath.opacity_at()` 的钳制就是为这件事存在的。

## 6. 召唤层 SUMMON

### 6.1 Tab「看一眼自己」— 签名画面

全游戏唯一出现数字的地方（GDD §11），所以它必须是最好看的一帧。

#### 三条设计立场

1. **时间不停。** 这是生存游戏，看自己是要付代价的。顶部的阶段进度弧仍在走，这是给玩家的提醒
2. **信息中心是雪地里那个人，不是屏幕边框。** 五段弧环绕角色本人，不是仪表盘
3. **冻伤是局部的**（GDD §5），所以手弧与足弧长在角色剪影的实际肢体位置

#### 构成

```

   ┌────────────────────────────────────┐

   │  饥饿 41%        ╭╯  ▲   ╰╮        │   半径 = 1.6 × 角色屏幕高
   │  口渴 33%        │  ╱人╲  │        │   段间 14° 空隙
   │  疲劳 77%        ╰╮ ╱  ╲╭╯        │
   │  冻伤 —          ╰─┴──┴─╯         │
   │                   ↑    ↑           │
   │                  手弧  足弧         │
   │                                    │
   │              你拥有 40:00 的火      │   ← 底部
   │              负重 12.4 kg           │
   └────────────────────────────────────┘
```

#### 弧的规格

| 项 | 值 |
|---|---|
| 圆心 | 角色的屏幕投影位置（相机是正交且不旋转，投影恒定） |
| 半径 | 1.6 × 角色屏幕高度 ≈ 1.6 × 11% × 1080 = **190px** |
| 段间空隙 | 14° |
| 底槽 | 2px `line/deep` |

**体温占 110°，位于正上方，是其余四条的近两倍。** 它是主时钟，是唯一致死的一条（`lethal_at_min = true`），层级必须在视觉上说出来。

#### 状态表现

| 情况 | 表现 |
|---|---|
| 正常 | `ink/primary` 静止 |
| 净速率 > 0（恢复中） | 弧末端一个 `life/warm` 的 3px 点缓慢前移。**这是暖色，因为热量正在进入身体** |
| < 0.25 | 转 `alarm/blood` |
| < 0.15 | 加 `颤`，并像将熄的火一样明灭（0.7 Hz，振幅 40%） |
| 已归零 | 弧变成一段 1px 的空槽。**不是红色，是空的** |

#### 数字

左侧呼吸边界内，纵向排列，Instrument L 28 + 标签 Caption 14：

```
体温   68 %
饥饿   41 %
口渴   33 %
疲劳   77 %
冻伤   手 82 / 足 61
```

**必须是表格数字**，否则每一帧都在抖。

#### 底部两行

```
你拥有 40:00 的火
负重 12.4 kg
```

**「你拥有 40 分钟的火」是这个游戏最好的一个数字。** 它直接来自 `FuelEconomy.fuel_seconds()`，而那个函数的注释写着「THE number of GDD section 5：water, food, warmth and five beacons are all bought out of it」。

把它显示成秒数（`2400 s`）是对的但是冷的；显示成 `40:00` 并配上「的火」两个字，玩家立刻明白他手上握着的是**时间**，不是木头。

#### 进出

- 按下 Tab：`呵·重` 320ms。世界压暗 35%（`scrim/veil`），四角霜迅速内长，弧顺时针依次绽放（每段延迟 60ms）
- 松开 Tab：`散` 600ms。弧同时消散，不逐条

### 6.2 1-5 速用

| 操作 | 行为 |
|---|---|
| 轻按数字键 | 立即使用该槽物品，触发拾取回执样式的**使用回执**（§5.3 同款，文案为 `喝下 · 融水`） |
| 长按 >180ms | `呵` 出五槽横条，位于底部呼吸边界内，居中。松手 `散·快` |
| 槽空 | 数字 `ink/muted` 24%，无图标 |
| 不可用（如未融化的雪） | 图标 `ink/muted`，下方 Caption 说明为什么：`要先化开` |

最后一条直接对应 `fuel_economy.gd` 的 `consume()` 拒绝逻辑——雪没有 `hydration`，所以吃它是**不可能**而不仅仅是没用。UI 必须把这个"不可能"说清楚，否则玩家会以为是 bug。

### 6.3 F 举枪锁定

准星锚在目标的世界坐标上（规则 5）。

- 四段弧构成的断环，缓慢逆时针旋转
- 锁定过程中环从 48px 收拢到 28px，`呵·重` 320ms
- 锁定完成：环停转，`alarm/blood` 闪一次
- **手部冻伤时环会抖**，抖动幅度 = `(1 - aim:steadiness) × 6px`。这个通道 `survival_system.gd` 已经发布，数据在 `frostbite_hands.tres` 里（<0.5 时 0.7，<0.2 时 0.6）

**准星是召唤层的，松开 F 就消失。** 它不是常驻准星（规则 4）。

### 6.4 火炉环形菜单

在火炉的交互提示上按 E，环形菜单在火炉的世界坐标上展开。

```
              添柴
        融雪    ●    烹饪
              取消
```

- 四个扇区，半径 96px，扇区之间 8° 空隙
- 扇区不是色块，是**弧 + 图标 + 标签**（规则 1）
- 图标 32px，标签 Body L 22
- **每个选项都标着它的代价，单位是秒**：

| 选项 | 代价显示 | 数据来源 |
|---|---|---|
| 添柴 | `+10:00`（柴 600s） | `ItemDefinition.fuel_value` |
| 融雪 | `−1:30` | `snow.tres` 的 `heat_seconds = 90` |
| 烹饪 | `−2:00` | `canned_stew.tres` 的 `heat_seconds = 120` |

- 不可用选项 `ink/muted`，代价加删除线，下方 Caption 说明：`火里的柴不够` / `没有雪` / `已经有热汤了`

后三种拒绝理由**逐条对应 `stove.gd` 的 `heat()` 里的四个 `return &""` 分支**。这张表是 UI 与那个函数的契约——`heat()` 静默返回空字符串，UI 的职责就是把那个沉默翻译出来。

- 「添柴」展开二级环，列出手上每种燃料及其数量与秒数

## 7. Juice 清单

十二项，全部可独立开关（便于验收与降级）：

| # | 名 | 规格 |
|---|---|---|
| 1 | **呵气凝结** | 每个元素诞生时 blur 4px→0，配 scale 过冲 1.02 |
| 2 | **微过冲** | `呵` 曲线末端到 1.02 再回落，位移类元素过冲 3px |
| 3 | **雪粒穿越** | 世界的雪粒渲染在 UI 层**之上**，UI 因此在世界内部而不是贴在镜头上 |
| 4 | **温度呼吸** | 所有 `life/warm` 元素 0.25 Hz 明暗，**相位与火焰的实际闪烁同步** |
| 5 | **冻结抖动** | 体温 <0.15 时全部笔画 12 Hz / 1px 抖 |
| 6 | **触发涟漪** | 交互确认时从世界锚点扩出 22→64px 的环 |
| 7 | **结霜边缘** | 四角霜随体温连续生长，程序化生成，不用贴图 |
| 8 | **声画同帧** | 每次 `呵` 都有配音（§8） |
| 9 | **惯性拖尾** | 移动中的元素留 2 帧残影，不透明度 24% / 12% |
| 10 | **消散上飘** | `散` 时 translateY -8px，像真的呵气 |
| 11 | **入夜心跳** | 入夜时一记 45 Hz 低频，配合边缘扫掠 |
| 12 | **暖色溢出** | `life/warm` 元素向外溢 3px 辉光，`life/ember` 溢 2px |

**第 3 项是最便宜也最有效的一项。** 让雪粒盖在 UI 上面，UI 立刻从"贴在屏幕上的东西"变成"在世界里的东西"。技术上只是 `CanvasLayer.layer` 的排序。

**第 4 项的相位同步是第二便宜的一项。** `stove.gd` 已经在 `light_energy_now()` 里算出了火的实时能量（燃料低于 `light_fade_seconds` 时线性衰减），UI 直接读这个数就行——于是火将熄时，屏幕边缘那条线也跟着弱下去，两者永远不会说不同的话。

## 9. 输入表补全

`project.godot` **目前没有 `[input]` 段**。四个移动动作是 `player_controller.gd` 在 `_register_actions()` 里运行时注册的，`door.gd` 同样运行时注册 `interact`。

那是切片期的正确做法（"真正的输入表加进来后会覆盖它"是两个文件都写明的），但 UI 落地需要一张真表。下表是 GDD §11 的完整实现：

| 动作名 | 键盘 | 手柄 | 出处 |
|---|---|---|---|
| `move_forward` / `back` / `left` / `right` | W A S D / 方向键 | 左摇杆 | GDD §11 |
| `run` | Shift | L3 | GDD §11 |
| `interact` | E | A / ✕ | GDD §11 |
| `aim_lock` | F | LT / L2 | GDD §11 |
| `look_at_self` | Tab（**按住**） | 触控板 / Select（按住） | GDD §11 |
| `quick_use_1` … `_5` | 1 – 5 | 十字键 + RB 组合 | GDD §11 |
| `pause` | Esc | Start | — |
| `ui_confirm` / `ui_cancel` / `ui_up` / `ui_down` | Enter / Esc / ↑ / ↓ | A / B / 左摇杆 | Godot 内置 |
| `debug_lighting_panel` | F1 | — | 已存在，仅 debug build |

**注意 `look_at_self` 是按住型**，不是切换型。这是 GDD 写死的（「Tab（按住）」），也是设计上的：切换型会让玩家把它开着不关，那就变成 HUD 了。

## 10. 实施批次

UI 是纯消费方，不改任何系统代码。但它依赖的事件分布在不同波次，所以分四批：

| 批 | 内容 | 依赖 | 可并行 |
|---|---|---|---|
| **U0 · 地基** | 设计令牌资源（`data/ui/tokens.tres`）· 字体导入 · `UILayer` 自动加载 · `呵/持/散` 动效工具类 · 图标资产导入 | 无 | — |
| **U1 · 呼吸层** | 交互提示 · 阈值浮现 · 拾取回执 · 昼夜更替 · **时刻提示** · 火 · 室内 | U0 · 全部事件**已存在** | 三项可并行 |
| **U2 · 召唤层** | Tab 看自己 · 1-5 速用 · 火炉环形菜单 | U1 · `FuelEconomy` **已存在** | — |
| **U3 · 框架层** | 主菜单 · 设置 · 暂停 · 三种结局 | U2 · **需要 `game_state.gd`**（系统地图任务 29） | — |
| **U4 · 后挂** | F 锁定准星 · 威胁褪暖 · 天气预兆边缘 | 波次 3（天气）· 波次 5（威胁） | — |
| **U5 · 蒙太奇** | 空间排版 · 蒙太奇导演 · 影像分级 · 开场三镜 | U0 · **不依赖任何未完成的波次** | — |

**U1 现在就能开工**——它需要的每一个事件都已经在跑。

**U0 与 U5 已交付**（`c96fcbf` · `10b3f42` · `e378e69` · `97fa62e` · `fed0088` · `31b8cfe`）。U5 排在最后但先做了，因为它不依赖 `game_state.gd`——而且它是唯一一块能在屏幕上**被看见**的，为其余部分定住了这套语言的成色。

**U3 被 `game_state.gd` 卡住**，因为主菜单需要"是否存在进行中的一局"这个信息，而现在没有任何东西拥有它（`run_boot.gd` 的注释把这个空缺写得很清楚，它自己就是那个临时替身）。**U3 开工前必须先做系统地图任务 29。**

## 11. 把 UI 规则变成测试

照抄美术圣经 §6 的做法。UI 规则不该靠自觉维持。

| 测试 | 路径 | 检查 | 失败条件 |
|---|---|---|---|
| 无硬编码色 | `tests/art/test_ui_palette.gd` | 扫描 `src/ui/**` 与 `scenes/ui/**` | 出现十六进制字面量或不在令牌表内的 Color |
| 暖色语义 | `tests/art/test_ui_warmth.gd` | 扫描使用 `life/warm` 的节点 | 出现在选中态、hover、通用强调上 |
| 无常驻元素 | `tests/unit/test_ui_lifetime.gd` | 每个呼吸层元素 | 缺少 `散` 定时器或时长为 0 |
| 呼吸边界 | `tests/unit/test_ui_safe_area.gd` | 每个 UI 节点的矩形 | 侵入中心 85% 区域 |
| 文案覆盖 | `tests/unit/test_ui_threshold_copy.gd` | 遍历 `data/stats/*.tres` 的每条 `ThresholdEffect` | §5.2 文案表里没有对应行 |
| 被遗弃结局 | `tests/unit/test_ui_abandoned_ending.gd` | 该结局的场景树 | **存在任何 Control 节点** |

**已落地的（§4.5 / §5.9 / U0）**：

| 测试 | 路径 | 检查 | 失败条件 |
|---|---|---|---|
| 令牌不漂移 | `tests/unit/test_ui_tokens.gd` | 每个令牌 vs 调色板 | 令牌不是 §2.1 点名的那个调色板条目 |
| 暖色只有三个 | 同上 | 九个令牌逐一 | 第四个令牌是暖色 |
| 包络 | `tests/unit/test_breath.gd` | 过冲峰值、落点、单调性、三条缓动曲线的两端 | 峰值不是 1.02、不落回 1.0、退场变亮 |
| 字体链顺序 | `tests/unit/test_ui_fonts.gd` | **测量**同一串字过三条路径的宽度 | 链条测出来是 Noto 的宽度而不是 Cormorant 的 |
| 空间三属性 | `tests/unit/test_inscription.gd` | billboard / 深度测试 / alpha 模式 | 任一条被改掉 |
| 描边不留 | 同上 | 退场结束时的 `outline_modulate.a` | 描边比字形活得久 |
| 元素自尽 | `tests/unit/test_ui_layer.gd` | 包络结束后的 `live_count()` | 元素活过了自己的呼吸 |
| 镜头不丢 | `tests/unit/test_montage_director.gd` | 一次长 delta 跨多镜 | 中间镜的公告被吞掉 |
| 题字不越镜 | 同上 | 切镜后的 `live_inscription_count()` | 上一镜的字还站在世界里 |
| **文字放得进镜头** | `tests/unit/test_montage_data.gd` | 每一个授权镜头 | `text_start + 行时长 > duration` |
| 读数层与阈值表一致 | `tests/unit/test_vital_readings.gd` | 每条状态的值与它的阈值区间 | 读数层对某条状态的判断与 `VitalTone` 不同 |
| 时刻提示的周期是关系 | `tests/unit/test_time_prompt.gd` | `seconds_between()` vs 当日日程 | 周期变成一个与日程无关的常数 |
| 时刻提示活在边界内 | 同上 | 五种窗口形状下的矩形 | 元素高于呼吸边界，或伸进中心 85% |
| 弹性不在 alpha 上 | 同上 | `呵·重` 的不透明度曲线 | 出现过冲（>1）或非单调 |
| 阈值浮现看得见 | `tests/unit/test_threshold_ink.gd` | 五种**实测**地面下选中的墨 | 低于该地面上色板能给的天花板 |
| 分界线是一条关系 | 同上 | `DARK_GROUND_BELOW` vs 两支墨的亮度、`deep_night` 的估计值、实测最暗的亮场 | 常数落到三条边界之外（改一个色号就该红） |
| 一处分界线，不是两处 | 同上 | `UIInk` vs `TimeArc` | 时刻提示与阈值浮现对「暗场」的判据不同 |
| 图标、弧、文案同墨 | 同上 | 两种地面 × 三种状态 | 三者之中任何一个跑掉 |
| 对比度不靠底板解 | 同上 | 扫描 `src/ui/threshold_note.gd` | 出现 `draw_rect` / `StyleBox` / `ColorRect`（规则 1） |

**下面三项是本节的重点。**

「文案覆盖」把 §5.2 那张表变成了一条机器约束：**加一条阈值而不写文案，测试就红**。没有它，第一条被遗忘的阈值会静默地什么都不显示，而这种失败在屏幕上和"这条阈值还没触发"完全一样。

「被遗弃结局」把 §4.4 的那条规则变成了机器能执行的东西。这是全项目唯一一个**断言某处必须没有 UI** 的测试，它守的是这个游戏的艺术落点。

「文字放得进镜头」守的是同一类沉默失败。一行的时长由字数算出，所以**改一行文案就可能让它放不进原来的镜头**——而放不进的表现是最后几个字在切镜时丢在半空，看起来像渲染故障。

> **「字体链顺序」值得单独说，因为它是这套测试里唯一一条不能靠读配置来验的。**
>
> 顺序写反的链条**仍然是一条合法的链条**——读回配置看不出任何问题。所以这条测试**测量**：把同一串拉丁文字设三遍（过链条、只过 Cormorant、只过 Noto），先断言后两者**确实不同**（否则测量什么也证明不了），再断言链条等于 Cormorant。写反时，三个宽度会一起打进失败信息里。
>
> 这一招**不能**用在中文上：每个全角字形都精确前进 1em，无论哪套字体画的，所以宽度比对在那边永远返回假阴性。这个坑在浏览器原型里先付过一次学费，才没有在 Godot 里再付一次。

## 12. 非目标（明确不做）

- 小地图 / 指南针 / 路径点 / 任务追踪 —— 违反「距离即风险」，GDD §13 已否决快速旅行，导航同理
- 常驻状态条 —— 违反规则 4
- 对话框 / 教程弹窗 —— GDD §2 明文否决
- 成就 / 统计面板 / 图鉴
- 物品栏网格 —— 携带物由 1-5 与 Tab 读数表达，没有需要整理的背包
- 存档槽位 —— 永久死亡，一局就是一局
- UI 主题换肤
- 难度选项 —— GDD §13。§4.2 的辅助项**不改变任何生存数值**，那是无障碍不是难度
- **日次转换的蒙太奇** —— 见 §4.5。它发生在游戏进行中，叙述塞进去就撞第三支柱
- **「被遗弃」结局的任何文字** —— 见 §4.4 与 §4.5。那个结局的力量全在于什么都没发生
- 可跳过之外的蒙太奇交互 —— 蒙太奇不是一个界面，它是一段镜头
