# 交接：Director 席位

这份文档交接的是**位置**，不是进度。进度在 git 里，而 git 永远比这份文档新。

**你接手的角色是 Director**——制作人、系统管理者、派活的人。你不亲自写游戏代码，你决定做什么、派给谁、验收标准是什么、以及在两个正确的意见冲突时谁赢。

这份文档写于 2026-08-12，当时有五条 agent 线在跑。你读到它的时候，那些线的产出早已落地，而下面任何"当前状态"的句子都可能已经过期。

**所以先跑这三条，用仓库校准自己：**

```bash

git status --short
```

**以仓库为准，不以任何文档为准，包括这一份。**

同一个错误后来又犯了一次：他在生成 HUD 图标之前没有查现有资产，而项目里早就躺着那条线做好的 20 个图标，比他生成的更贴合设计文档。

## 2. 工作方式：one job, one fresh agent

**每一件事派一个全新的 agent。**不要自己写游戏代码——你的上下文是用来做判断的，不是用来写实现的。

### 派发的形状

一份好的派发包含：**这件事在项目里的位置** · **要做什么** · **判据（怎么算做对了）** · **不许碰哪些文件** · **报告写到哪里**。

不要重复 `AGENT-BRIEFING.md` 里的东西——那份文档存在的意义就是让派发词从 900 字降到 150 字。让 agent 自己去读。

### 四条从实践里长出来的规矩

**一、`do not touch` 必须逐条列出，写文件路径。**同时跑三到五条线时，冲突不是抽象风险——`scenes/main.tscn` 是本仓库最抢手的文件，两个 agent 曾各自用 `git hash-object` 手工组装提交来避开对方。

**二、验收要能被执行，不能是形容词。**"做好看点"不是判据。"抓三次不同的惊飞并排放，如果看起来像同一个镜头放了三遍，那变化就是失败的"才是。

**三、要求它复现自己所防的缺陷。**新建一道门禁？把坏东西放回去，证明它会红。**一个复现不了缺陷的门禁，本身就是下一类假通过。**

**四、明确允许它反驳你。**写上"如果你判断我说的是错的，说出理由比服从更有价值"。这不是客气话——它救过很多次（见第 4 节）。

### 并发上限

**四到五条线是这个仓库的实际上限**，而且必须文件不重叠。超过之后，agent 报告里"另一个 agent 的未提交工作让我这次运行变红"的比例会显著上升。

## 3. 这个项目已经付过学费的七类假通过

**全部记在 `AGENT-BRIEFING.md` 里，这里只列清单让你知道要警惕什么形状：**

1. 解析失败 → 整个文件的测试静默不跑
2. 运行时中断 → 断言之后的代码全不执行，仍报 PASS
3. 三个美术门禁只在**空文件夹的循环里**断言
4. 往返测试只验存、不验取
5. `play()` 返回 `true` 而引擎一个音都没放（44 次）
6. **1317 个测试各自都对，而它们从不见面**——两个真实系统放进同一棵树立刻崩
7. **着色器在更晚的一帧编译，整个套件活在第一帧之内**——一个语法上死掉的 `.gdshader` 可以让套件全绿

**第七类尚未关闭**，修法只需一行（`RenderingServer.force_draw()`），条件是等着色器工作线安静。见 `DEFERRED.md`。

`tools/run_tests.sh` 是这套体系的核心仪器：它在测试全绿时仍会因为控制台有一行 `ERROR:` 而判失败。**它带着一条极窄的第三方白名单**（整行精确匹配、每条附理由、每次抑制都打印）。**不要为了让运行变绿而拓宽它。**

## 4. agent 纠正你，是这套体系在正常工作

上一任 Director 在一天之内被 agent 纠正了**六次**，每一次 agent 都对：

| 他的判断 | 实测 |
|---|---|
| 角色"趴在地上" | 平面着色 + 45° 俯角，动画没问题 |
| 房间"被雪埋了" | 是**地形**比地板高 0.6 m，雪只有 7 毫米 |
| 树的碰撞体是凸包 | 项目里**一个凸包都没有**；真因是几何被连续放大三次（+885%） |
| 屏占比 11.4% / 8.9% / 7.1% | 实测 8.5% / 6.7% / 5.2%——公式假设直立人形，角色是佝偻的 |
| "地面丢了对比度" | **根本没有回归**；两帧不是同一个镜头，因为速度改了、跟随相机落在不同地面上 |
| "把冻伤并进体温" | 冻伤是**局部的**（手/脚各有后果），是自己的东西 |

**规律不变：站在场景里拿探针的 agent，胜过看着截图推理的 Director。**

所以：**你的裁决要建立在测量上，或者明确标注"这是假设，去验证"。**上一任在派发里区分"我验过的"和"我猜的"，那个习惯值得继承。

还有一条相关的：**当你用一个词描述你想要的效果时，那个词可能自带一个错误的实现方式。**他三次因此造成可见问题——"粗化噪声"自带低频、"暗晕"自带模糊渐变、"描线"自带第二层笔画。**描述效果时把禁止项一起说出来。**

## 7. 三件工具上的事

**生图**：技能 `gemini-image-gen` 已装在 `~/.claude/skills/`，跑通过。模型是 `gemini-2.5-flash-image` @ `us-central1`，走 `generateContent`。**成套图标必须用 `New-IconSet.ps1`**——单张能出图 ≠ 能出一套，模型不会在多次调用间保持构图一致。**生成前先查 `assets/ui/icons/`，那里已经有 22 个。**

**Blender MCP** 可用，`tools/blender/build_*.py` 能重跑。**重跑是 Director 的排期决定**，因为它会和别人的工作撞车。

**Godot 编辑器**：所有者常开着它，而**它每次保存都会吃掉 `.tscn` 里的注释**（一次吃掉 51 行），也会重写 `project.godot`。**不要从 shell 和编辑器抢方向盘**，也不要把承重的文档写进场景文件。

## 8. 最后一句

这个项目最贵的东西不是代码，是**那些"看起来对但其实错"的东西被抓住的记录**——七类假通过、15 个引擎陷阱、六次 Director 被纠正。它们全部写在 `AGENT-BRIEFING.md` 和 `DEFERRED.md` 里，而且**每一条都附着当时的测量数据**。

新加一条的时候，照那个格式写：**症状 · 实测 · 为什么它会骗过人 · 怎么办。**

「为什么它会骗过人」是最值钱的一栏。缺了它，下一个人读到的只是一条规则，而不是一次教训。
