# WinterTime UI/UX 深度打磨提案

日期：2026-08-13
性质：设计与交付提案；本文件不修改游戏代码或资产。

## 结论

WinterTime 不需要一套更“华丽”的 HUD；它需要把已经很好的 **BREATH（呵气）** 设计语言，做成一套在压力下仍可读、可控、可感受的玩家体验。当前 UI 的主要问题不是审美方向错误，而是完成度不均：基础令牌、动态包络、阈值文案、时刻弧与测试很扎实，但玩家真正需要的交互闭环（目标提示、物品回执、Tab 自检、速用、火炉菜单、暂停与设置）尚未落入主场景和输入表。

审计建议的北极星是：

> 让玩家先从世界感到寒冷、距离与希望；只有在必须作出决定的那一瞬，界面才像呼在镜头上的一口气，给出足够明确的下一步，然后消失。

可从《纪念碑谷》借鉴的是“几何、留白与运动本身说明可行动性”的安静清晰感；可从《Endling: Extinction is Forever》借鉴的是“压力由关系、声音和环境后果承担，而不是被一排仪表解释”的同理心。两者只作为高层原则，不复制其构图、图标、字体、音效或具体 UI 形态。

## 审计范围与证据

已阅读 GDD、美术圣经、系统地图、UI/UX 设计文档、AGENT-BRIEFING、当前 `src/ui/`、`data/ui/`、相关单元测试及 `scenes/main.tscn` 的接线。并以项目真实场景与捕获工具运行了以下样本：

- `capture_time_prompt`：白天/夜晚、Day 4、相位进度 35%/72%；运行时元素均为 141×49 canvas px。
- `capture_threshold_note`：明亮雪地与深夜两种状态。
- 深夜“手指不听使唤了”的实际核心对比度为 **2.70:1**；明亮雪地为 **6.52:1**。前者不足以可靠支撑 17px 左右的正文阅读，特别是在移动、雪粒和疲劳状态叠加时。

运行时日志也确认项目已启用 `addons/godot_ai`，并由 `godot_ai game_helper` 注册了捕获能力；本会话未暴露可直接调用的 GodotAI MCP 工具，因此上述审计使用同一插件支撑的项目内真实捕获路径，而非静态 mock。

### 现状矩阵

| 区域 | 已有且值得保留 | 当前缺口 | 用户可感知后果 |
|---|---|---|---|
| 视觉语言 | 12 色表派生、无矩形、暖色仅代表热量、呼吸边界 | 缺少把这些规则统一应用到实际交互组件的组件库 | 看得到“局部漂亮”，还感受不到一整套体验 |
| 动效 | `Breath` 的呵→持→散、退出顺序、时间缩放、自动释放 | 缺少输入、成功、拒绝、危险之间的明确动效层级 | 动画有诗意，但操作反馈不完整 |
| 状态提示 | 阈值文案、`ThresholdSurfacing`、时刻弧、真实场景捕获与对比测试 | 夜间文字读不稳；同一屏幕锚点会把不同事件压成同一种语气 | 玩家可能错过“现在必须改变计划”的信息 |
| 召唤层 | `VitalReadings`、`VitalPaint`、`VitalStroke`、`Frost`、`VitalLayout` 等基础件 | 没有 `Tab` 视图实例和输入接线；速用/火炉环形菜单未落地 | 最需要决策时没有可靠的信息与操作闭环 |
| 输入 | 角色移动、冲刺、门交互和镜头缩放已存在 | `project.godot` 没有完整正式输入表；无 Tab/1–5/F/暂停/手柄映射和重绑界面 | 设计文档里的可玩交互无法被真正发现或使用 |
| 框架层 | 蒙太奇与题字已实现 | 主菜单、暂停、设置、可访问性页面依赖 `game_state.gd`，尚未实现 | 不能构成可发布体验，也没有让玩家调节舒适度的入口 |

`main.tscn` 当前 UI 仅接入 `UILayer`、`ThresholdSurfacing` 与 `TimePrompt`。这不是失败，而是清楚说明优先级：不要先继续微调一条 141px 的时间弧；先完成它本应服务的玩家循环。

## 设计原则：保留与强化

以下原则已经正确，应视为不可倒退的创作约束：

1. **世界优先，界面第二。** 中心 85% 仍属于雪地、角色、道路、火与生物；不用常驻任务、地图、血条或准星取代观察。
2. **暖色是资源，不是装饰。** `life/warm` 仅表示热量正在抵达、火仍可用或信标正在活着；选择、焦点与确认用冷色明度、描边与运动表达。
3. **每条信息必须能回答一个决定。** 不显示“你很冷”，而显示“手脚开始发僵”；下一处火、门、信标、足迹和声音继续承担导航。
4. **呼吸层必须可预测。** 每个提示都有出现、停留、散去；高风险可以更重，但不能突然闪现或留下永久残影。
5. **召唤层是承诺，不是例外。** Tab 按住时显示数字是合理的，因为它由玩家主动换取注意力；松开即散，时间继续走。
6. **无障碍是另一条感知通道，不是一套“简单模式”。** 调节字体、对比、抖动、闪烁、字幕和重绑，不改变天气、流失率、死亡或资源经济。

## 目标体验架构

### 一、三种信息力度

所有视觉、音频和手柄反馈归入三档，避免每个事件都抢同样的注意力。

| 力度 | 触发 | 画面 | 声音/触觉 | 例子 |
|---|---|---|---|---|
| 轻声 `whisper` | 已知、可逆、无即时抉择 | 1px 冷色笔画；短 `呵`；2 秒后散 | −28 dB 霜裂；无手柄震动 | 拾取、门成功打开、时刻变化 |
| 提醒 `call` | 需要玩家重估路线或资源 | 文字 + 图标/弧的次序；3–4 秒；可在边界安全区出现 | 木/雪触感；短单脉冲 | 融雪被拒、火将熄、阈值越过、天气预兆 |
| 警报 `alarm` | 立即威胁生命或不可逆承诺 | 不增加面板；让边缘霜、焦点、呼吸节奏和世界锚点共同加强 | 低频、方向性世界声；可选双脉冲 | 体温临界、熊发现玩家、信标熄灭、死亡 |

同一时刻只允许一个 `call` 或 `alarm` 占用注意力。低优先级事件进入一个 2–3 秒的合并窗口，例如“拾到木柴 ×2”，而不排成通知队列。死亡、信标熄灭与威胁发现具有明确抢占权；被抢占的低级信息直接丢弃，而不是延迟到已经不相关时再弹出。

### 二、四个空间域

| 域 | 允许内容 | 锚点与边界 | 禁止内容 |
|---|---|---|---|
| 世界 `diegetic` | 门、火、炉、拾取物、信标、威胁、可交互对象 | 优先 3D 锚点；被遮挡时折到最近安全边缘并以细引线保持来源关系 | 屏幕中心说明文字、永久浮标 |
| 呼吸边界 `breath` | 阈值语句、时刻、轻回执、短暂控制提示 | 7.5% 呼吸边界；按左/下/右分配槽位，避免所有事件固定在左上 | 卡片、背景板、堆叠通知中心 |
| 召唤 `summon` | Tab 身体读数、火炉径向菜单、短按/长按速用、F 锁定 | 玩家主动按住/接近；数字只在此域出现 | 切换型“常开”状态窗 |
| 框架 `frame` | 主菜单、设置、暂停、结局 | 运行外或明确暂停；允许更克制的留白与镜头 | 在活跃探索时覆盖游戏 |

当世界坐标不可读时，屏幕锚定是允许的，但必须保留“这是来自哪里”的关系：方向缺口、引线、声源方位或对象轮廓至少保留一种。这样既不牺牲可读性，也不把信息变成脱离山谷的弹窗。

## 具体视觉与交互提案

### 1. 先修读性，再增加装饰

夜间阈值提示的 2.70:1 核心对比度必须作为 P0 缺陷处理。解决方法不应是黑色矩形底板，也不是放宽测试：

- 为 `ThresholdNote` 与 `TimeArc` 建立同一套**实测背景亮度—墨色—字重**策略；暗雪上使用 `ink/primary`，但以呼吸层已授权的 CJK 600 / Latin 500 字重、最少 Body 17 的真实渲染结果为验收依据。
- 对正文目标设为 **至少 4.5:1 的已送达核心对比度**；纯图形弧与图标至少 3:1。达不到时优先变更字号、字重、可用的色表阶梯、笔画厚度和位置；不新增色、不引入矩形。
- 把极低对比的“静态时刻词”降为纯氛围信息；涉及生存抉择的阈值、拒绝原因与输入动作必须满足正文标准。
- 雪粒可继续压在 UI 前方以保留世界内感，但不得遮挡关键文本笔芯超过 10% 连续 250ms；发生时短暂降低该区域雪粒密度，而不是取消全局降雪。

### 2. 阈值提示：从“诗句”到“可行动的诗句”

保留现有文案表的克制语气，但为 `call` 级事件增加一个 14px 的**后果/方向副句**，仅当玩家第一次遇到该阈值或行动可能不明显时出现。例如：

```
手脚开始发僵
靠近火源可缓解
```

第二行不是数值、不是教程弹窗，也不是每次都显示；它是一次性的行动翻译。之后只保留第一行，以免诗意退化为操作日志。危急阈值不用长文：让笔画碎颤、边缘霜和低频承担强度，文字仍只说一句。

阈值提示应从固定左上改为**边界槽位调度**：身体类在左侧、时间/天气在下侧、威胁方向在靠近其方位的侧边；每个槽位最多一条。当主角或交互对象的世界关系更有意义时，优先给出世界锚定版本。

### 3. 时刻提示：让时间像方向而不是一个小标签

当前下方弧的克制正确，但在夜间可读性与层级偏弱。保留“日/月端点—当前刻度—弧”的核心，优化为：

- 弧宽随短边为基准（现有行为保持），但标题组的光学高度增加约 15–20%，先靠字重/字距，再考虑字号；不可仅放大图标。
- `白天 Day 4` 的混排改成**一个主语、一个低声副语**：本地化语言优先；英文仅在国际化版本或作为可关闭的副语。中文发行版建议 `第四日 · 白昼`，避免“白天 Day 4”把两个语言系统竞争成同级标题。
- 日/月端点不是按钮，不能看起来像可点击控件；当前端点和“现在”刻度之间应以进度、而非更亮的图标，表达时间方向。
- 在过渡瞬间，弧的 `bloom-heavy` 可以和环境光、音乐换面同步；日出不叠加 UI 音，入夜低频保留为可关闭的“危险信号”。

### 4. 交互提示与径向菜单：让物体教会玩家

这是最适合吸收《纪念碑谷》式“空间即说明书”的部分。

- 接近门、炉、信标、拾取物时，只出现**世界锚定的细弧 + 动词 + 输入 glyph**：`E · 推开`、`E · 添柴`。物体本身在焦点变化时以极轻的轮廓/光照响应，不使用外发光描边。
- 可执行：冷色主笔画完整；不可执行：`ink/muted`，并把拒绝原因放在动词下方，如“火里的柴不够”。不给仅靠颜色的禁用态。
- 按下输入后先给 80–120ms 的“压实”反馈；成功用向外 22→64px 的涟漪，失败用向内收紧 6px 的弧并返回原因。成功与失败的声音必须不同，且都不抢世界音。
- 火炉菜单只在炉子世界坐标展开；扇区用弧、图标、标签和秒数代价，默认选中跟随摇杆/鼠标方向。释放输入确认，`B/Esc` 永远关闭并恢复上一焦点。若相机将其压到边缘，径向菜单整体向可视半平面偏移，但中心点仍由一根细线指回炉火。

### 5. Tab 自检：应成为整个项目的“签名交互”

现有 `VitalReadings`、`VitalPaint`、`VitalStroke`、`Frost` 和 `VitalLayout` 已为此准备，下一阶段必须把它做成真正可玩而非测试孤岛。

按住 Tab / Select 时，时间不暂停；玩家被允许短暂凝视自己。角色周围的五段断弧比任何角落仪表更贴近游戏主题：身体是地图，火与温度是时间。

- 先显示温度主弧，再依次出现饥饿、口渴、疲劳、手/足冻伤；60ms 的相位差让观看路径从“活下去”再到“为什么做不到”。
- 所有数字与标签限定在呼吸边界，但每条读数与角色的对应弧保持视线关系。手/足冻伤绝不能并成抽象总条。
- `life/warm` 只在净恢复时作为沿弧移动的 3px 热点出现；低值用空槽、断续和呼吸不稳表达，红色仅用于伤害/死亡。
- Tab 开启有 `scrim/veil`，但世界仍能辨认、输入仍响应；玩家无法借它“暂停找答案”。松开即散，焦点回到世界。
- 手柄：按住 View/Select；键盘：Tab。手势必须同时支持，不把精致 UI 限定给鼠标键盘。

### 6. 快捷使用、瞄准、威胁与信标

- 1–5 的短按立即使用，长按只在底部边界展示五个槽；槽位可用性必须有文字或形状差异，不能只变色。
- F/LT 锁定环只能在目标存在时出现；手部冻伤用可选的低幅摆动与稳定性变差表达，不能以持续大抖动妨碍瞄准。
- 威胁反馈优先使用**方向性世界声、动物姿态、风向、足迹和视野焦点**；UI 只补最小方向缺口。熊、饿汉等不能用红箭头或血量条。
- 信标是希望的主视觉：远处以真实光、烟、声音和位置建立方向；被吹灭时让暖色撤退、世界声消失，并给一次性 `alarm`。不要做常驻“五个信标清单”。

### 7. 框架层与诗意叙事

主菜单、暂停与设置可比游戏内 UI 更具排版性，但仍应保持“雪地上的题字”而非产品化 dashboard：

- 主菜单：一张受控的无人物世界镜头；标题为 Display XL；单列文字导航；焦点用冷色笔画粗细与轻位移表达，非暖色按钮。
- 暂停：冻结世界而非铺满遮罩；在边界内排列“继续 / 设置 / 退出此局”。初始焦点是继续，Esc/Start 永远可返回。
- 结局：保留“被遗弃”无文字、无 Control 的规则。另两种结局允许极少题字、环境声和镜头，不用统计结算和奖牌。

## 输入、可访问性与感官舒适度

这些是发布前的产品要求，不应作为“以后再做”的装饰项。

1. **正式输入表。** 将移动、冲刺、交互、Tab、速用、瞄准、暂停以及全部菜单动作写入 `project.godot`；运行时注册仅保留为兼容回退。键盘与手柄必须每项都有等价路径。
2. **重绑。** 设置中允许键盘与手柄分别重绑；检测冲突、说明不可冲突的基础动作，并在保存后立即更新界面 glyph。
3. **输入反馈。** 焦点、按下、成功、拒绝、长按进度、关闭各自有可区分的形状/声音；键盘焦点永远可见，菜单不产生焦点陷阱。
4. **文字与对比。** UI 缩放 80–150%；高对比模式使用同一官方色表中的合法墨色/描边组合、加厚笔画和降低雪粒遮挡，绝不新加荧光色或面板。
5. **运动与闪烁。** “减少动态”保留状态变化但去除过冲、拖尾、12Hz 抖动与额外霜生长；“减少镜头震动”独立控制。持续闪烁不得超过 3Hz；紧急信息要有静态形状/文字等价物。
6. **音频与字幕。** UI 音量独立；方向性环境提示提供短暂、可关闭的字幕/方向标签（例如“左侧 · 熊的呼吸”），不做常驻环境日志。听觉提示不能是唯一危险通道。
7. **色觉与认知。** 低温、恢复、损伤、禁用必须同时由弧的完整度、纹理、运动或文字表达；不依赖暖/红/蓝区分。所有重要提示有可预测的固定语序：**对象 → 变化 → 可行动信息（仅首遇）**。

## 实施路线：以独立 fresh job 交付

每个 job 由一个新的实现 agent 执行，开始时只读取 AGENT-BRIEFING、此文的相关小节、任务简报和必要代码；完成后由另一 fresh reviewer 验收。任何 job 发现需求冲突、触及未批准的系统设计或无法用现有事件表达时，必须停止并请求所有者裁决，而不是猜测。

| 阶段 | Fresh job | 产出与边界 | 退出标准 |
|---|---|---|---|
| P0 | `ui_evidence_gate` | 统一真实捕获、亮度/遮挡/输入焦点测量；不改玩法 | 白天、深夜、雪天三组捕获；正文对比、雪遮挡、边界占用均有机器报告 |
| P1 | `ui_input_foundation` | 正式 InputMap、手柄默认映射、输入 glyph 和重绑数据接口；不实现菜单美术 | 所有 GDD 动作可被自动输入测试；没有运行时注册依赖；冲突规则有测试 |
| P2a | `ui_interaction_breath` | 目标提示、拾取/拒绝回执、边界槽位调度、音频状态机 | 真实门/炉/拾取场景可捕获；成功/拒绝/离开三态清晰且自动清除 |
| P2b | `ui_readability_access` | 阈值和时刻提示的实测对比、缩放、低动态、高对比、字幕接口 | 夜间正文核心 ≥4.5:1；五种窗口形状、三种预设、三档缩放均通过 |
| P3 | `ui_summon_body` | Tab 身体读数的完整接线；只消费现有事件/数据 | 按住/松开、五条读数、恢复暖点、手足冻伤、时间继续走均有集成测试与捕获 |
| P4 | `ui_summon_actions` | 1–5 速用、F 锁定、炉火径向菜单 | 键盘和手柄路径一致；禁用原因/取消/边缘避让可测试 |
| P5 | `ui_frame_accessibility` | 在 `game_state.gd` 之后实现菜单、暂停、设置与重绑页面 | 焦点循环、Esc/Start 返回、缩放与设置持久化、结局禁 UI 均通过 |
| P6 | `ui_world_pressure` | 连接 Wave 4/5 的信标、天气、威胁世界提示 | 不引入常驻任务或威胁条；白茫环境中方向和威胁仍可通过至少两个通道感知 |

P2a 与 P2b 可并行；P3 依赖 P1 与 P2b；P4 依赖 P1 与已有炉火/物品接口；P5 依赖 `game_state.gd`；P6 随 Wave 4/5 到来。每个 job 只提交它自己的文件，不与当前雪地、足迹或音频工作线混合提交。

## 测量与测试计划

单元测试是必要条件，真实场景捕获是体验验收条件；两者不可相互替代。

### 必须新增或升级的自动化门禁

- **`test_ui_delivered_contrast`：** 用真实字体、抗锯齿、实际背景与三个光照预设测正文、图标、弧；正文 4.5:1，图形 3:1。
- **`test_ui_occlusion_budget`：** 雪粒、霜、镜头和 UI 叠加时，关键笔芯连续遮挡不超过阈值；同时守住“雪在 UI 前”的艺术规则。
- **`test_ui_attention_arbiter`：** 同时触发拾取、阈值、天气、威胁时，确认只有最高优先级显示，低级事件被合并或丢弃，不会晚到。
- **`test_ui_input_contract`：** GDD 全部动作均存在键盘、手柄和必要菜单路径；Tab 为按住型；Esc/Start 总能取消；不存在焦点陷阱。
- **`test_ui_accessibility_modes`：** 三档 UI 缩放、减少动态、高对比、字幕开关不会侵入中心 85%，且不改生存数值。
- **`test_ui_warmth_semantics`：** 新组件不能把 `life/warm` 用于 hover、选择或通用确认；恢复热点、火、信标是仅有合法来源。
- **`test_ui_lifetime_and_slotting`：** 呼吸层都经由 `UILayer` 释放；一个槽位只出现一个 call/alarm；对象离开交互范围走快速散去。
- **`test_ui_no_control_abandoned_ending`：** 保留并扩展现有“被遗弃结局没有 Control”的绝对约束。

### 人工体验验收脚本

每次视觉变化至少跑一轮，不把“截图看上去漂亮”误当作可玩：

1. 白天出门、进深雪、回火边：玩家是否仅凭世界与一次阈值提示理解为什么该回家？
2. 深夜、风雪、低温：在不看 Tab 的情况下是否仍能感到危险；按 Tab 后是否能在两秒内读到哪个系统最紧急？
3. 炉火资源不足：玩家是否明确知道动作被拒的原因，以及下一步可做什么？
4. 键盘、Xbox/PlayStation 布局、纯手柄三轮：是否能发现、打开、确认、取消每一种 UI？
5. 150% UI 缩放、高对比、减少动态、字幕开启：中心世界是否仍保持，所有关键变化是否仍可察觉？
6. 未来熊/饿汉与信标场景：关闭 UI 音或关闭颜色区分后，玩家是否仍有至少两条独立危险/方向通道？

## 需要所有者裁决的点

以下问题改变产品语气或范围，不能由实现者自行决定：

1. 中文正式版本是否保留英文副语（如 `Day 4`），还是完全本地化为“第四日 · 白昼”？本提案建议后者，英文版本再显示其自身语言。
2. “靠近火源可缓解”这类一次性行动副句，是否接受？它能明显降低早期困惑，但比纯诗句多一步指导。
3. 高对比模式是否允许短暂降低关键文字区域的雪粒密度？本提案建议允许，因为它不改变世界/数值，只保证信息抵达。
4. 是否将方向性环境字幕作为默认开启、可关闭的无障碍选项？本提案建议默认关闭、首次启动可见说明，避免把静默叙事变为文字流。

在以上裁决前，可安全开始 P0、P1 与 P2a 的基础工作；P2b 可以先建立测量门禁，但不要武断改变文案和雪粒策略。

## 完成定义

当玩家在暴风雪里看见远处信标、听见一侧威胁、感到自己正在失温，仍无需常驻 HUD 就能做出“继续、回家、添柴还是绕路”的选择；而当他主动按住 Tab，身体与时间又以一张安静、清晰、令人记住的画面显现——这套 UI 才达到了本项目所说的 AAA 级完成度。AAA 在这里不等于屏幕上有更多东西，而是每一笔、每一声、每一次消失都恰好帮助玩家活在这个世界里。
